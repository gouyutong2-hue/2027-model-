# 08 层次分析法｜让项目选型有依据

**对应讲义** 《数学建模算法.html》第 7 节与《第八章 层次分析法》§1–2（讲义印刷页 167–174）。预计 65–90 分钟。

读完能写出判断矩阵、求层次单排序和总排序、检查一致性，并用权重敏感性判断一个方案是否值得推进。

## 1. 用成对问题分解一场选型会议

假设 iGEM 团队正在选择一个样本处理流程。目标是“选可以在学期内稳定运行的方案”，准则可以是速度、成本、可靠性，方案层放三个候选。先确定任何方案都须满足的硬约束，再比较余下方案。每张判断矩阵只回答一个问题，例如“为了本轮选型目标，速度相对成本有多重要”或“在速度这一项上，流程 A 相对流程 B 有多好”。

对同层 $n$ 个元素做 $n(n-1)/2$ 次独立比较，填 $a_{ij}$ 并以倒数填 $a_{ji}$，对角线为 1。讲义的 1、3、5、7、9 表示从同等到极强偏好，2、4、6、8 是中间等级。例如“速度相对成本偏好 3”填速度行、成本列为 3，反向填 $1/3$。使用测量值时要先确定方向和效用。两个方案分别花 100 和 200 元，若假定成本效用为实际费用倒数，较便宜方案对较贵方案的比较值才是 2。若有固定预算断点，可先设可行性约束或按明确价值函数打分。

| 讲义步骤 | 手边应有的产物 | 检查 |
|---|---|---|
| 目标、准则、方案分层 | 决策图和准则定义 | 速度与同义的处理量可能重复计权 |
| 两两比较和 1–9 标度 | 一张准则矩阵，每个准则下一张方案矩阵 | 矩阵互反，行列对象顺序一致 |
| 单排序与一致性 | 主特征向量 $w$、最大特征值 $\lambda_{\max}$、一致性比率 CR | 权重非负且和为 1 |
| 总排序与一致性 | 每个方案的加权得分及该层合成 CR | 接近的名次要做权重情景比较 |

程序求 $Aw=\lambda_{\max}w$，将正主特征向量归一。完全传递的判断满足 $a_{ij}a_{jk}=a_{ik}$，此时 $\lambda_{\max}=n$。令 $CI=(\lambda_{\max}-n)/(n-1)$，查同阶随机一致性指标 $RI$ 得 $CR=CI/RI$。1 阶、2 阶互反矩阵在本课直接报告 CR 为 0。常用回访阈值为 0.10。偏好循环过强时，把具体冲突的三项比较拿回决策会议重问。

把各准则下的方案权重向量按列放入矩阵 $B$，把准则权重放在向量 $w$ 中，总得分为 $Bw$。按讲义，方案层合成一致性可算 $\sum_j w_j CI_j / \sum_j w_j RI_j$。CR 衡量判断是否自洽。重复计权、数据质量和价值偏好还需要单独核对。

## 2. iGEM 原项目｜2013 UESTC 的 Nebula

UESTC 在 2013 iGEM World Championship 提交的 Nebula 把团队整理的元件信息放入数据库。手动模式让用户连接元件，自动模式从用户给定的输入和输出出发，按可用性、用途、样品／元件状态及测序等属性对元件和连接评分，再按加权路径找候选。其软件仓库顶层列出 Web 和 iOS 实现，竞赛手册第 17 页明确记载 AHP 与按边权寻找最短路径。公开仓库目录可定位到版本，但具体权重矩阵、依赖与旧服务的运行结果尚未核验。[官方竞赛手册第 17 页 UESTC／Nebula](https://static.igem.org/mediawiki/2013/d/d1/2013_WCJ_program_-_merged_new.pdf) · [UESTC 原软件仓库](https://github.com/igemsoftware/UESTC2013)

按作者公开设计可重建这样一条计算链。先把对象和允许的连接整理成图。然后用 AHP 将多个准则转成权重，把各条边的准则值合成边代价。最后固定起终点寻找累计代价最低的路径。教学代码 `nebula_analogue` 用抽象样本处理流程重建这一构造，准则为速度、成本及可靠性。每条边给定三项已归一、越小越好的虚构代价，权重约 $[0.540,0.163,0.297]$，Dijkstra 选出 **Start → Batch reader → Review → Done**，总成本约 **0.569**。边权可以相加是这个示范的明确假设。若经过某一步后另一条边的代价改变，需要扩展图状态或另建约束。

脚本还用同一准则权重演示完整 AHP 层次总排序。三个直接比较的教学方案的得分约 0.417、0.405、0.178，合成 CR 约 0.019。直接方案打分与图中的逐边代价是两套练习数据。原项目的重点是让自动模式从大量候选中筛出可审查的路径，评分主要反映数据库记录与提前规定的准则。

## 3. 论文案例｜给七种微藻收获技术排序

Albaqi 等 2022 年比较七种用于微藻生物原油生产的收获方案，以能耗、成本、污染风险、收获效率、技术可用性、藻株适用性和生产时间为准则。原文表 4 的能耗、成本、效率、时间汇自文献，定性准则源自专家判断，表 5–7 给出对应比较矩阵。输入混合了跨研究的定量信息与采集的偏好判断，因此方案选择需先确认本地的处理规模和边界条件。[Albaqi 等原论文](https://doi.org/10.22146/free.v1i1.3847) · [全文表 2–9](https://journal.ugm.ac.id/v3/FREE/article/download/3847/1750)

1. 作者先写出“选收获工艺”的目标与七项准则，用表 2 的互反矩阵求表 3 的准则权重。脚本用特征向量复算，这七项权重四舍五入至三位小数均与表 3 一致。
2. 作者再产出每项准则内的七个方案分数。使用表 8 已发表的局部权重与表 3 的列序做矩阵乘法，可直接复算总分。原文 §3.2 展示了离心的乘法，帮助核对表中容易被误读的列序。
3. 论文报告絮凝—沉降第一，随后为有机絮凝和错流过滤。重建得分依次为 0.201995、0.160900、0.158571，排序保持一致。若分数按常规三位小数舍入，错流过滤的复算值为 0.159，论文表 9 为 0.158，页面给出的局部权重仅三位小数，足以影响此处的末位。
4. 公开数值还有两处应保留的差异。论文段落将效率与技术可用性的权重分别表述为 0.133、0.066，按表 2 的矩阵、表 3 及离心乘法，列权重应分别读为 0.066、0.133。本章采用后三处互相一致的读法。用讲义的 $RI_7=1.32$ 由表 2 复算的 CR 是 0.0783，论文表 3 为 0.076，工具版本及 RI 约定尚未在公开正文中核实。两值均在 0.10 的常用阈值以下。

本章复算的数值链是“表 2 → 准则权重”和“表 3 + 表 8 → 表 9”。表 4 每列原始量到表 8 方案分数的完整映射与原始逐份问卷在所核验的材料中缺乏足够复算信息。合成后的名次适合用来筛选候选，靠近的两名要看权重和效用变化导致的交叉。

## 4. 本机复现

在课程目录、已安装依赖的环境执行。只需 Python、NumPy 和 SciPy，小矩阵与短路径均可在普通 CPU 上运行。Excel 也可核算局部权重乘加和情景表，Python 则便于保留取舍及复算记录。

```bash
python examples/ahp.py
```

- AHP 适合候选少、准则有定性成分、需要把专家意见留痕的研究选型。准则很多时，成对问题以平方量增长，可用少量核心准则加可核验的效用评分。能耗和成本互相影响时，先检查是否把同一来源的效应计权两次。若团队目标受明确的预算和最低可靠性约束，可先用约束筛选，再对可行方案画 Pareto 前沿，保留不同偏好都可能成立的方案。准则间关联是研究重点时，还可以考察支持依赖网络的 ANP。[Bottero 等在食品加工废水选型中对照 AHP 和 ANP](https://www.sciencedirect.com/science/article/pii/S1364815211001009)
